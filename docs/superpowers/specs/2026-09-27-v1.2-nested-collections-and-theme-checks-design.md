# tilder 1.2: nested collections and theme checks - design

Date: 2026-09-27. Status: approved in conversation (the owner's choices:
recursive collections in tilder; both theme checks moved into tilder),
awaiting review of this document. Implementation plan to follow.

Asked for by the tilder website: its documentation is a tree of folders,
and its theme carried two checks (`tools/check-theme.py`,
`tools/check-contrast.py`) that belong to the generator.

---

## 1. Goal

1. **Nested collections.** A collection may read its folder recursively:
   `content/docs/guide/install.md` is an item of `docs`, served at
   `/docs/guide/install`, listed in the collection's order, its sidebar
   and its neighbours, with the folder as its section.
2. **Theme checks.** `build.py --check` checks the site's theme against
   the contract of the tilder that builds it: every class the builder
   writes has a rule in `style.css`, and the colour pairs the theme
   declares meet their contrast minimum. The build itself is unchanged.
3. `AGENTS.md` §6 says what the scripts may fetch now that the example
   CSP has `connect-src 'self'`: same-origin files only.

A site that sets nothing new changes by not one byte.

### Not in this work

- Nested DATED collections (a blog by year folder): refused with an error.
- Contrast of anything but CSS custom properties of `:root` (and its
  `prefers-color-scheme: dark` twin).
- Running the checks during a normal build.

## 2. Nested collections

### 2.1 Switch

A collection key, `recursive` (default `false`). The built-in types leave
it `false`; a type may default it in its `DEFAULTS` (the documentation
theme's `doc` type sets `true`). A DATED type with `recursive = true` is
a collection error ("a dated collection cannot be recursive").

### 2.2 What is an item

In a recursive collection's folder, at any depth:

| File | Item slug | Page path |
|---|---|---|
| `docs/install.md` | `install` | `docs/install.html` |
| `docs/guide/install.md` | `guide/install` | `docs/guide/install.html` |
| `docs/guide/index.md` | `guide` | `docs/guide.html` |
| `docs/guide/deep/index.md` + `shot.png` | `guide/deep` | `docs/guide/deep.html` |
| `docs/index.md` | not an item | the collection's own page, as today |

- The rule for `<folder>/index.md` is the existing item-folder rule: the
  page sits beside the folder (`docs/guide.html`), files next to it are
  copied. A folder may hold both its `index.md` and further items: it is
  then a **section** whose own page is `docs/guide.html`.
- Language suffixes, `_`-prefixed templates, fallback: as today, per file.
- An item's `collection` is the collection; `item["slug"]` carries the
  path (`guide/install`); `item["section"]` is the folder part (`guide`,
  `""` at the top).

### 2.3 Order

The order is a depth-first walk: within a folder, entries (items and
sections) are sorted by the type's `sort_key`; a section sorts by its own
`index.md` item (or, without one, by its folder name, after the items
that have a key); a section's own page comes first, then its content.
Lists (`{docs}`), feeds, `outputs()`, `{{ collection_nav }}`,
`{{ prev }}`/`{{ next }}` and the text line all use this order.

### 2.4 The sidebar

`{{ collection_nav }}` becomes a tree when the collection has sections:

```html
<nav class="collection-nav" aria-label="In this section">
<ul>
	<li><a href="install">Install</a></li>
	<li class="collection-section"><a class="collection-section-label" href="guide">Guide</a>
	<ul>
		<li><a href="guide/writing" aria-current="page">Writing</a></li>
	</ul>
	</li>
</ul>
</nav>
```

- A section's label is its `index.md`'s title, linked; without one, the
  folder's name, as a `<span class="collection-section-label">`.
- The section holding the current page gets `class="collection-section
  collection-section--open"`; the theme may fold the others.
- `group:` keeps working inside any level, as in 1.1.
- New classes: `.collection-section`, `.collection-section--open`,
  `.collection-section-label`.

### 2.5 Everything else

- The `<h1>` wordmark already names every folder of a page's URL; a
  section's own page names that segment.
- The text mirror's line (SEQUENTIAL) follows the depth-first order.
- `paths.ITEM_FOLDERS` records nested item folders as today.

## 3. Theme checks

### 3.1 The command

```sh
python3 builder/build.py --check        # checks, then exits: 0 fine, 1 a check failed
```

It builds nothing. It prints one line per problem in the report's usual
shape (`error: theme/style.css: no rule for .toc-label`) and a summary
line per check. Without `theme/style.css`, the class check is skipped
with a note. It is the command the website's `Makefile` runs before a
build, and CI may run too.

### 3.2 Classes

- The contract becomes data: `src/contract.py` holds `CLASSES`, the list
  of every class the builder writes (today's table of `docs/theme.md`).
- A test keeps `docs/theme.md`'s class table and `CLASSES` equal.
- The check: every class of `CLASSES` appears as a selector in
  `style.css` (the rules of the theme's tools/check-theme.py, moved:
  comments stripped, `.name` not followed by a name character).
- A theme may declare classes it deliberately leaves unstyled, in
  `theme.toml`: `[check] unstyled = ["icon"]`.
- The starter theme passes the check (it must style every class,
  `AGENTS.md` §5): the classes it lacks today are added.

### 3.3 Contrast

- `theme.toml` declares the pairs: `[check] contrast = [["--text",
  "--bg"], ["--muted", "--bg"], ...]`, with an optional
  `contrast_min = 4.5` (WCAG AA for text).
- The check reads the custom properties of `:root` and of the `:root`
  inside `@media (prefers-color-scheme: dark)` in `style.css` (hex
  colours; anything else is an error naming the token), computes the
  WCAG 2 ratio of each pair in each scheme, and reports every pair below
  the minimum with its ratio. Without `[check] contrast`, skipped.
- `--check --markdown` prints the contrast table as Markdown, for a
  theme's README.
- The starter theme declares its pairs and passes.

### 3.4 Docs

`docs/theme.md` gains a "Checking a theme" section (the command, the
`[check]` table, what each check reads); `README.md` mentions
`--check`.

## 4. Tests

- Recursive items: slugs, paths, section, item folders at depth,
  language fallback per file, `_` templates, DATED + recursive refused.
- Order: depth-first, sections by their index's key, index first.
- Sidebar tree: sections, labels with and without `index.md`, `--open`
  on the current section, `group:` inside a section; prev/next across
  sections; text line.
- A non-recursive collection with subfolders: output unchanged.
- `--check`: a theme missing a class (named), `unstyled` honoured,
  contrast failure (named with ratio), both schemes, malformed token,
  no `style.css`, `--markdown` table; exit codes 0/1; builds nothing.
- `CLASSES` equals `docs/theme.md`'s table; the starter passes `--check`.
